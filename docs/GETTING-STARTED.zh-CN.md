# Branchlet 入门：安装、连接 Git 与项目使用

[简体中文](GETTING-STARTED.zh-CN.md) · [English](GETTING-STARTED.en.md) · [返回首页](../README.md)

本指南面向第一次使用 Git 图形工具的 Windows 用户。Branchlet 在浏览器中显示界面，由本机 Git 完成实际操作；不需要先注册 Branchlet 账号。

## 1. 安装与启动

### 使用 Windows 便携包

1. 从 [Git 官方 Windows 安装页](https://git-scm.com/install/windows) 下载并安装 Git for Windows。使用普通安装器即可；保留 Git Credential Manager，并选择让 Git 可用于命令行和第三方程序的选项。
2. 获取维护者提供的 `Branchlet-<version>-windows-x64.zip`。项目有已发布版本时，在实际项目的 Releases 页面下载这个附件；不要把自动生成的 “Source code (zip)” 当成便携包。
3. **完整解压**到有写权限的文件夹，例如 `D:\Apps\Branchlet`；不要在压缩包内直接运行，也不要只复制启动脚本。
4. 双击 `Start-Branchlet.cmd`，等待浏览器打开 [本地工作台](http://127.0.0.1:4317)。如果浏览器未自动打开，可手动访问该地址。

此包包含应用和 Node.js 运行时，因此电脑只需要额外安装 Git for Windows。无需执行 `npm install`，也无需单独安装 Node.js。界面和示例操作可离线使用；访问远程仓库、登录和发布 Release 需要相应网络连接。

需要停止启动器管理的服务时，双击同一目录中的 `Stop-Branchlet.cmd`。关闭浏览器标签页不会停止后台服务；停止脚本只会处理这份应用启动并记录的对应进程。

### 手里只有源码时

完整解压源码后，同样可双击根目录的 `Start-Branchlet.cmd`。启动器依次查找随包运行时、缓存运行时和兼容的系统 Node.js；没有时从官方来源准备缓存的便携运行时。首次会安装依赖并构建应用，需要联网，也会比便携包启动慢。它仍不要求用户手动安装 Node.js。源码更新后，先停止旧实例，再执行 `Start-Branchlet.cmd -Rebuild` 重新安装锁定依赖并构建。

开发者的命令行方式在 [贡献指南](../CONTRIBUTING.md) 中说明。源码开发使用 `5173`，正常启动和便携包使用 `4317`。

## 2. 先在示例中练习

首次启动会自动打开 `atlas-workspace`。它是独立的真实 Git 仓库，包含提交、分支、标签、储藏、待提交文件，以及指向本机裸仓库的 `origin`。

1. 点击「仓库文件」，通过列表或目录树了解项目结构，选择文本文件查看内容。
2. 点击「工作区更改」，选中文件查看右侧 Diff；绿色表示新增，红色表示删除。
3. 点击文件右侧 `+` 暂存，或选择「全部暂存」。
4. 在提交说明中输入 `docs: 完成第一次图形化提交`，点击提交。
5. 打开「提交历史」，选择新提交，查看作者、哈希和内容。

示例推送只更新本机示例远程。它不会上传到 GitHub，也不会重置你已经完成的练习。

不需要示例时，点击侧栏中示例仓库旁的移除按钮并确认。它会从仓库列表中移除，重启后也不会自动出现；磁盘上的示例文件、提交和练习进度仍保留。需要时可通过「打开仓库」重新选择原路径，默认是应用数据目录下的 `demo/`。

## 3. 打开、创建或克隆自己的项目

| 你的情况                               | 操作                                                           |
| -------------------------------------- | -------------------------------------------------------------- |
| 电脑上已有 Git 仓库                    | 点击「打开仓库」，输入 / 选择项目文件夹                        |
| 电脑上已有普通文件夹，希望开始版本管理 | 切换到「新建仓库」，选择文件夹并创建；默认初始分支为 `main`    |
| 想新建一个空项目文件夹                 | 在「新建仓库」输入新文件夹的完整路径，随后在编辑器中创建文件   |
| 项目已在 GitHub / GitLab 等远程服务上  | 切换到「克隆仓库」，粘贴克隆地址，选择一个新的或空的目标文件夹 |

### 选择其他盘符或直接输入路径

点击路径旁的文件夹浏览按钮，在目录选择器中选择可访问的 Windows 盘符，例如 `C:\` 或 `D:\`，再进入项目文件夹。也可以在目录地址栏输入完整路径，例如 `D:\projects`，点击前往按钮或按 `Enter` 跳转，然后选择当前文件夹。若盘符或目录不可访问，检查是否已连接该磁盘以及当前用户的访问权限。

创建尚不存在的文件夹时，直接在仓库路径输入框中填写完整新路径，例如 `D:\projects\my-project`；目录浏览器用于选择已有目录。

打开仓库后，先检查顶部路径和当前分支。Branchlet 会直接修改这个项目的工作区、暂存区和 Git 历史。文件浏览页用来阅读内容，文件创建与编辑仍在自己的编辑器中完成。

侧栏中每个仓库都可移除。此操作只删除应用列表中的记录，保留项目文件和 Git 历史；之后可按原路径重新打开。移除当前仓库后，应用会切换到其他仓库；列表为空时可继续打开、新建或克隆项目。

### 填写提交作者

进入「设置」，填写作者名称和邮箱并保存。这些值仅设置当前仓库，并记录到之后的提交中。作者名称 / 邮箱**不是登录账号**，不会让你获得远程推送权限。

## 4. 连接远程 Git

Git 管理本地版本；GitHub、GitLab 等服务保存远程仓库。先在所用服务上创建 / 找到目标仓库，再复制它的 HTTPS 或 SSH 克隆地址。

### 推荐从 HTTPS 开始

Git for Windows 包含 Git Credential Manager（GCM）。需要认证时，它可以引导浏览器登录并复用保存的凭据；公开仓库的只读克隆一般不需要登录。[GitHub 官方凭据说明](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git)

Branchlet 的 Git 子进程关闭交互式终端提示。如果私有克隆、拉取或推送提示认证失败，可以先在独立 PowerShell / Git Bash 窗口完成一次凭据登录。将下面的 `OWNER/REPOSITORY` 替换成**你自己有权限访问的实际仓库**：

```bash
git ls-remote https://github.com/OWNER/REPOSITORY.git
```

对需要认证的仓库，按 GCM 出现的浏览器提示登录；命令成功后返回 Branchlet 重试。对公开仓库，此只读命令可能直接成功而不会触发登录；如果之后公开仓库推送仍需凭据，可使用 `git credential-manager github login` 完成 GitHub 登录后再试。不要把密码或令牌拼进远程 URL。

### 可选：已有 SSH 配置

如果你已经配置好 SSH 密钥，可直接使用 `git@github.com:OWNER/REPOSITORY.git`。首次 SSH 主机信任或密钥口令应先在独立终端完成，再回到应用。完整密钥配置参见 [GitHub SSH 指南](https://docs.github.com/en/authentication/connecting-to-github-with-ssh)。

### 本地新项目的第一次推送

1. 在 GitHub 等服务上新建远程仓库。已有本地提交时，为减少初次历史冲突，可使用未初始化 README / 许可证的空远程仓库。
2. 在 Branchlet 打开本地项目，完成作者设置、暂存和至少一次提交。
3. 打开「远程仓库」→「添加远程」，名称填写 `origin`，地址填写实际仓库的克隆 URL。
4. 点击「推送」，核对目标仓库与分支后确认；成功后会设置上游。

正常协作时，「获取」更新远程引用；「拉取」将当前分支快进到远程进度；「推送」发送本地提交。领先 / 落后数字来自已获取的引用，先获取可以更新它们。拉取采用 `--ff-only`，双方都有新提交造成分叉时，需要先按项目约定处理分支关系。

## 5. 日常操作

| 任务         | 方法与效果                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| 阅读项目     | 「仓库文件」切换列表 / 树、进入文件夹、选择文本预览；被 Git 忽略的内容和 `.git` 内部不作为普通项目文件展示 |
| 审阅改动     | 「工作区更改」区分未暂存和已暂存；选择对应分组中的文件读取各自 Diff                                        |
| 提交部分文件 | 只暂存本次需要的文件，再填写说明并提交；目前按整个文件暂存                                                 |
| 取消暂存     | 已暂存列表点击取消，保留工作区文件内容                                                                     |
| 放弃改动     | 点击丢弃并确认；已跟踪文件恢复未暂存改动，未跟踪文件会被删除                                               |
| 切换任务     | 先提交或储藏当前更改，再创建 / 切换分支；新建分支成功后会切换过去                                          |
| 合并分支     | 在分支管理中把所选分支合并到当前分支；安全删除会拒绝未合并分支                                             |
| 临时保存工作 | 储藏包含已跟踪和未跟踪文件；应用保留记录，弹出在成功后删除记录                                             |
| 撤销历史改动 | 提交详情的「撤销提交」创建新的逆向提交，保留已有历史                                                       |
| 发布版本文件 | 使用「GitHub Releases」，详见 [发布指南](RELEASING.zh-CN.md)                                               |

在外部编辑器修改文件后，点击「刷新」读取新状态。应用不持续监听磁盘。

### 冲突怎么处理

工作区会标记冲突文件；正在进行的合并、拣选、撤销或变基显示状态横幅。

1. 点击「查看工作区」，用编辑器解决文件内的 `<<<<<<<`、`=======`、`>>>>>>>` 标记。
2. 保存、刷新、暂存已解决的文件。
3. 冲突文件全部暂存后，点击横幅中的「继续」。后续步骤再次产生冲突时，重复处理。
4. 若要取消本次流程，选择「中止操作」并确认；冲突处理中的改动可能被撤销。

应用可以继续 / 中止外部启动的 rebase，但没有发起 rebase 或编辑交互式计划的界面。储藏冲突通常没有同类序列横幅，应在编辑器解决后暂存并按需要提交。

## 7. 数据、更新与范围

默认数据位于应用目录的 `.branchlet/`：`repos.json` 保存仓库路径，`demo/` 是示例工作区，`demo-origin.git/` 是示例远程。外部仓库不被复制；再次启动保留现有数据。更新便携包时，保留这份数据目录，不要用空目录覆盖它；自定义目录可设置 `BRANCHLET_DATA_DIR`。

例如从 PowerShell 设置数据目录再启动：

```powershell
$env:BRANCHLET_DATA_DIR = 'D:\BranchletData'
.\Start-Branchlet.cmd
```

主题和当前仓库选择存于浏览器本地存储，操作记录只保留当前页面会话。GitHub Releases 令牌只保留在本地服务内存中，断开连接或重启服务即清除。

- 提交历史加载最多 100 条，跨引用拓扑排序并排除储藏；搜索只覆盖已加载记录，没有分页。
- Diff 采用统一文本视图；目前没有编辑器、三方合并、逐行暂存或图片差异预览。
- 仓库文件每层最多显示 1000 项，文本预览最多读取前 1 MB、显示前 20,000 行；二进制 / 非 UTF-8 内容显示提示，符号链接仅显示名称，不跟随预览。
- 单次 Git 输出最多 4 MB，常规 Git 命令超时 30 秒，克隆 / 远程操作为 120 秒；单次文件操作最多 2000 个路径。
- 没有强制推送、硬重置、amend、分支重命名、远程标签删除和 PR / Issue 页面；支持推送标签，GitHub Releases 使用独立页面。
- Windows ZIP 面向 x64。它通过浏览器提供界面，不是 Electron / Tauri 安装程序。不要将本地服务作为公网服务部署。

## 8. 常见问题

| 现象               | 处理                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 提示找不到 Git     | 安装 Git for Windows，确认新终端中 `git --version` 成功，再重开启动器                                                               |
| 没有 Node.js       | 使用便携包即可；源码启动器也会在需要时准备运行时，首次需联网                                                                        |
| 双击脚本后失败     | 确认已完整解压到可写目录；查看启动窗口或 `.branchlet/server-error.log`，也可运行 `Start-Branchlet.cmd -Foreground` 直接观察服务日志 |
| 页面无法打开       | 检查服务是否仍在运行；手动访问 `http://127.0.0.1:4317`，检查是否已有实例占用端口                                                    |
| 提交失败：缺少作者 | 「设置」填写当前仓库名称和邮箱                                                                                                      |
| 远程认证失败       | 按第 4 节先完成系统 GCM / SSH 认证；提交作者设置和 Release token 不能替代 Git 登录                                                  |
| 拉取无法快进       | 获取后检查双方历史，在分支管理或终端按项目约定处理分叉                                                                              |
| 找不到刚编辑的文件 | 刷新；检查是否被 `.gitignore` 忽略，以及当前仓库路径 / 分支是否正确                                                                 |
| Release 403 / 404  | 检查目标仓库、令牌授权和组织审批；详见发布指南                                                                                      |
| 服务重启后会话失效 | 使用浏览器重新加载页面；应用内 `Ctrl+R` 只刷新仓库数据                                                                              |
| 仓库所有权不受信任 | 检查目录拥有者与 Git 信任设置，只信任自己确认过的仓库                                                                               |

更多开发配置见 [贡献指南](../CONTRIBUTING.md)，界面结构见 [UI 设计](UI-DESIGN.md)。
